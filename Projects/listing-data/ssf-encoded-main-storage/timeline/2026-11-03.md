Ok Ideal splitter plans, 

I have 3 ways to go about this. And I’m not entirely sure what will be batter or easier so I’ll try them… all. 

1. I send carts under the input cart at 64gt (so 8x hs assuming 64 items of a given item type) and  set a variable filter for each item type (by sending the cart over a hopper) and basically unload them over all loader slices, but this has a downside of needing like…. 27 maximum loader slices which isn’t a problem they all need this anyway but it assumes 64 items to be 8x so worst case scenario of 27 item types and only 1 item per it would take 1,728gt to process that cart. 

2. Do the exact same thing but instead of sending all carts over all filters it would do one item type at a time and allocate a loader to that item type as it goes. This seems better but checking for empty carts is kinda hard and would waste a few cycles of the 64gt carts so it would be even slower and it also assumes 64 items in a stack. So has the same speed issues but has the benefit of not needing 27 slices of loaders and can just use 1. 

3. Send 27 hopper carts under the input cart for 64gt and split them after the fact and do the same logic as one of the above options. This also assumes 64 items a stack but the speed loss is only applicable for 1 stack of items not 27 so it’s in theory 27 times faster. And means I will need those upwards of 27 slices of loaders again unless I make some logic to check for the same item type carts but that seems not worth the time to process that or the cost of doing all that over just doing 27 loaders at 8x each.
